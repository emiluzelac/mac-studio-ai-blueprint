01What 36 GB really means

On Apple Silicon, the CPU and GPU share one pool of memory. That's why a Mac can run models a gaming PC can't, but the whole model has to fit in that pool. Two numbers decide everything:

  • Capacity (36 GB) sets which models fit. macOS and your apps need about 8 GB, which leaves about 26–28 GB for AI.
  • Bandwidth (~460 GB/s) sets how fast they talk. Every generated word reads the active model weights from memory.

03If you ever upgrade

This machine sits at the entry point for serious local AI. The next steps up:

  • 64 GB or more (40-core M5 Max, ~614 GB/s): runs 70B-class dense models and keeps two models loaded at once. About 30% faster at generating text.
  • 128 GB+ / M5 Ultra: runs frontier-scale open models (100B+ mixture-of-experts) at usable speed.
  • External Thunderbolt 5 SSD: cheap model storage if the internal 1 TB fills up.

Honest limits. These models are excellent, but they're not frontier cloud models. For very large codebases, long autonomous agent runs, or the hardest reasoning, use Claude in the cloud. The local box is for privacy, offline use, and free unlimited use, and it covers most day-to-day needs.

05Using it day to day

At the desk

Open http://localhost:8080, or use the LM Studio app directly. Pick a model from the dropdown at the top.

From your phone

Turn on Tailscale and open your Mac's …ts.net address. In Safari, use "Add to Home Screen" so it works like an app.

Chat with documents

Drag PDFs or notes into a chat, or build a Knowledge collection in Open WebUI. Everything stays on the Mac.

Something feels slow?

Open Activity Monitor → Memory. If pressure is yellow or red, close big apps or switch to a smaller model or a shorter context.

06The build, phase by phase

Each phase ends with a check that must pass before moving on. With Claude Code, open Terminal in the folder that holds CLAUDE.md, run claude, and say "Build this."

Phase 1
macOS baseline. Update macOS, turn on FileVault (save the recovery key!) and the firewall. Set it never to sleep and to restart after a power cut. Install Homebrew, uv, and git, and create the ~/ai workspace.
Phase 2
GPU memory ceiling. Raise the GPU's memory limit from the default ~75% to 28 GB, which gives models room for longer conversations. It's a single setting and is made permanent with a boot script.
sudo sysctl iogpu.wired_limit_mb=28672
Phase 3
Engine. Install LM Studio, enable the lms command-line tool, and set the server to start at login on port 1234. It's reachable only from this Mac. Turn on idle auto-unload.
Phase 4
Models. Download the four models above as MLX builds. Start the context window at 32K tokens and raise it only while Memory Pressure stays green.
Phase 5
Chat interface. Install Open WebUI and run it as a background service that starts at login. You create your own admin account. Then turn off public sign-ups and connect document search.
Phase 6
Remote access. Install Tailscale and sign in on the Mac and your phone. tailscale serve publishes the chat app to your devices only. Never use "Funnel", which makes it public.
Phase 7
Extras. Voice transcription (mlx-whisper), image generation (mflux), and connecting code editors to the local API.
Phase 8
Benchmark. A script measures real speed and memory for each model and saves the results.
Phase 9
Maintenance. Time Machine backups of chats and settings (models are excluded because they can be downloaded again), plus status.sh and update.sh helper scripts.

07Rules of the road

  • Nothing is exposed to the internet. No router port-forwarding, ever. Tailscale is the only way in from outside.
  • One big model at a time. Two 15–20 GB models won't fit together.
  • Keep 150 GB free on the SSD. Models pile up quickly. Delete ones you don't use from LM Studio's "My Models" page.
  • Update monthly, not automatically. Run ~/ai/scripts/update.sh, then check that everything still works.
